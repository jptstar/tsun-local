# TSUN Local 1.4.0

TSUN Local 1.4.0 is a major compatibility and diagnostics release. It moves the integration from support centered on individual known models toward **TSUN local protocol-family compatibility**, while keeping the project strictly **local, read-only, cloud-free and proxy-free**.

## Highlights

- **1511 / TITAN** — validated on **TSOL-MP3000**.
- **02B0 / GEN3 PLUS** — validated on **TSOL-MX500**.
- **1097 / GEN3** — new experimental protocol support for community validation.
- Automatic protocol identification from the TSUN logger firmware where available.
- Progressive / dynamic PV-input detection instead of assuming a fixed number of inputs.
- Expanded inverter, logger, alarm and grid-protection diagnostics.
- Complete advanced grid-protection timing diagnostics exposed consistently in **seconds**.
- Home Assistant translations and entity documentation in **8 languages**.

## Protocol detection and setup

- Added firmware-guided protocol selection for logger firmware identifiers containing `1511`, `02B0` or `1097`.
- Added an explicit **Force protocol probing** mode for compatibility testing when firmware information is incomplete or misleading.
- Added direct `1511`, `02B0` and `1097` probing choices for controlled testing.
- Added diagnostics showing the firmware protocol hint and whether it matches the selected protocol adapter.
- Automatic network discovery now filters generic TCP port 8899 devices and proposes candidates whose local logger firmware identifies a supported TSUN protocol.
- Manual setup remains available when the logger firmware is unknown or the local logger web page cannot be read.

## PV detection and energy data

- Added progressive / dynamic PV-input detection across the supported protocol families.
- 1511 PV inputs are discovered from observed live or accumulated telemetry instead of always assuming six populated inputs.
- 1097 keeps the highest PV input actually observed and no longer treats an all-zero device as having six active PV inputs.
- Once detected, PV inputs are retained instead of disappearing after temporary zero-production periods.
- Corrected the 1511 per-PV daily-energy register positions from `base + 4` to `base + 5` for PV1 through PV6.
- Updated 1511 PV detection to use the corrected daily-energy positions.

## Grid-protection diagnostics

- Added complete read-only advanced grid-protection diagnostics for **1511** and **02B0**.
- Added voltage and frequency recovery thresholds.
- Added first-, second- and applicable third-level under/over-voltage protection values.
- Added first- and second-level under/over-frequency protection values.
- Added the associated grid-protection timing diagnostics.
- Corrected all supported grid-protection timing entities to use **seconds** in Home Assistant, with the existing `0.02` register scaling.
- Added a one-time migration for beta-era automatic `ms` display choices so existing entities return to `s` without overriding an explicit user-selected unit.
- Updated the entity documentation to match the seconds-based timing metadata and removed the provisional unit/scaling markers.
- Kept 02B0 register `0x202C` as a read-only **raw output coefficient** and removed the unconfirmed percentage unit. Values such as `1024` are no longer presented as `1024 %`.
- Advanced diagnostics are categorized as diagnostic entities and remain **disabled by default** to keep normal Home Assistant device pages uncluttered.

## Inverter diagnostics

- Added cross-protocol diagnostics for **raw inverter status**, **rated inverter power** and **maximum designed power** on 1511, 02B0 and 1097 where available.
- Added read-only access to the TITAN / 1511 native **A1/21 diagnostic block**, decimal registers `2000-2095`, collected at a slower diagnostic cadence.
- Added raw TITAN diagnostic entities for registers **3017**, **3018** and **3028** for continued hardware observation without assigning an unconfirmed physical meaning.
- Registers **3017** and **3028** are numeric raw-decimal measurement sensors so Home Assistant can chart their history while temperature mapping is validated. No `-40`, `-50` or other temperature offset is applied yet; 3018 remains a plain raw diagnostic.
- Register 3018 is optional and no longer breaks polling on devices or test fixtures where it is absent.
- Added a slow read for 02B0 register `0x2007`.
- Added a slow read for 1097 register `0x1437`.

## 1511 low-solar standby handling

- On validated MP3000 hardware, raw bit `0x2000` (`8192`) in global alarm word 1 is repeatedly observed at dawn, dusk and during very low irradiance.
- TSUN Local preserves that bit in `alarm_global_1_raw`, but no longer reports an inverter fault when it is the only active flag.
- A new inverter operating-state sensor reports **Standby — low solar input** for that observed condition.
- Any other active alarm bits continue to report **Problem / Fault**.
- The exact vendor bit-name for `0x2000` remains unconfirmed, so the integration deliberately describes the behavior from real-device observation rather than claiming an unsupported alarm-code mapping.

## Experimental 1097 / GEN3 support

- Added a new experimental **1097 protocol adapter**.
- Added standard inverter / AC and PV telemetry where exposed by the device.
- Added experimental diagnostics for:
  - protocol version;
  - inverter version;
  - inverter temperature;
  - insulation impedance RX;
  - insulation impedance RY;
  - raw country/profile value;
  - maximum designed power.
- 1097 support remains **experimental** until it is confirmed on more real devices.

## Logger and device information

- Added the logger Wi-Fi signal as a Home Assistant percentage diagnostic.
- Logger Wi-Fi signal refresh now has a true independent **five-minute timer**, including while inverter TCP polling is offline.
- Added the raw logger inverter profile reported by `inv_tp` to Home Assistant device information.
- The raw logger profile is used as device model information rather than being exposed as a separate diagnostic entity.
- Raw logger profile discovery is retried until it becomes available.
- Fresh logger metadata is preserved even if a later inverter poll fails.
- Logger metadata refresh is independent from inverter telemetry polling.
- Removed the obsolete **Raw logger profile** entity left by earlier beta builds and removed its unused translation key.

## Home Assistant UI, translations and documentation

- Added / completed advanced diagnostic entity names in:
  - English;
  - French;
  - German;
  - Dutch;
  - Italian;
  - Spanish;
  - Polish;
  - Simplified Chinese.
- Republished localized setup and protocol-selector strings so Home Assistant and HACS reload them correctly.
- Reworked the README around protocol-family compatibility instead of a short fixed model list.
- Added a complete protocol-oriented **entity reference** for 1511, 02B0 and 1097.
- Added clearer distinction between **validated**, **likely compatible** and **experimental** hardware.
- Updated the project website for the stable 1.4.0 release.

## Reliability fixes

- Preserved logger metadata and device information across temporary inverter communication failures.
- Preserved discovered PV topology across later polls.
- Kept optional diagnostic blocks from making the main telemetry update fail.
- Cleaned up obsolete beta-only entity-registry artifacts.

## Safety and architecture

- All new inverter and logger access remains **read-only**.
- No inverter configuration write has been added.
- No grid-protection setting write has been added.
- No inverter control command has been added.
- The 02B0 output coefficient is read but never written.
- Logger discovery and metadata identification use local read-only HTTP requests.
- TSUN Local requires **no cloud service and no proxy** in the Home Assistant data path.

## Upgrade note

The advanced grid-protection timing entities use **seconds**. If an earlier beta caused Home Assistant to remember `ms` as the automatic display unit, 1.4.0 migrates that legacy automatic choice back to `s` while preserving an explicit user-selected unit.

Home Assistant **2026.3.0 or later** is required.
