# TSUN Local 1.5.1-beta.1

TSUN Local 1.5.1-beta.1 keeps the 1.5.0 Home Assistant alarm interface intact and adds a focused MP3000/TITAN field-validation update plus the logger Wi-Fi signal fallback fix.

## Highlights

- Fix **Logger Wi-Fi signal** remaining unknown when an earlier valid logger page did not contain RSSI: TSUN Local now continues through the available pages until `/status.html` exposes `cover_sta_rssi`.
- Add **10 read-only MP3000 A1/21 field-validation diagnostics**, all disabled by default.
- Expose the raw **1511 country/profile candidate** from decimal register `2000` (`0x07D0`). A live France-configured MP3000 reports raw `8`.
- Keep the adjacent `0x07D1 = 80` and `0x07D2 = 80` observations documented as a strong candidate pair for the two 40.0 s grid connection/reconnection settings, without assigning their individual semantic order yet.
- Preserve the complete **224-position MP3000 alarm catalogue** and the compact Home Assistant alarm interface introduced in 1.5.0.

## Country/profile candidate and attribution

The TSUN/Talent parameter export displays `France` with an exported `raw_value` of `1008`. That exported value is **not** treated as the local country enumeration.

Public protocol research by **Stefan Allius** in `s-allius/tsun-gen3-proxy` documents the country/profile enumeration used by the 1097 family, where **France = 8**, and maps the 1097 country/profile field at `0x1400`. TSUN Local explicitly credits Stefan for that discovery.

After applying the correct semantic country value, the MP3000/TITAN A1/21 dump shows:

- `0x07D0 = 8` — leading 1511 country/profile candidate for France;
- `0x07D1 = 80`;
- `0x07D2 = 80`.

The last two values each decode to 40.0 s with a candidate `×0.5 s` scale and line up with the TSUN/Talent grid connection and reconnection settings. Their individual order is deliberately left unassigned until an independent observation distinguishes them.

The `country_profile_raw` entity therefore exposes only the **raw local value** and remains an advanced diagnostic disabled by default. The 1511 semantic address is still under independent validation.

## Logger Wi-Fi signal

The local logger parser already understood values such as `cover_sta_rssi = "30%"`. The problem was traversal: a valid `/index_cn.html` or `/index.html` page without RSSI could stop the search before `/status.html`.

1.5.1-beta.1 continues through the logger status-page candidates until RSSI is found. A live dump after the fix successfully read **30% from `/status.html`**.

## Alarm regression policy

The 1.5.0 alarm architecture is intentionally unchanged:

- all **224** MP3000 bit positions remain covered;
- the 14 source alarm words remain available as disabled-by-default diagnostics;
- Home Assistant does not create 224 permanent entities;
- alarm codes and source-register/bit positions remain unique;
- the six PV alarm words continue to be decoded independently of PV-topology discovery.

## Safety

- All new MP3000 diagnostics are **read-only**.
- Logger metadata is read with local HTTP GET requests only.
- No inverter configuration write is implemented.
- No protection-setting write is implemented.
- No country/profile write is implemented.
- No inverter control command is added.

## Compatibility

- **1511 / TITAN:** validated on TSOL-MP3000; new field-validation diagnostics are beta candidates.
- **02B0 / GEN3 / GEN3 PLUS:** validated on TSOL-MX500.
- **1097 / GEN3 / GEN3 PLUS:** experimental; public mapping research is credited to Stefan Allius.

Home Assistant **2026.3.0 or later** is required.
