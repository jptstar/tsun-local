# TSUN Local 1.6.2-beta.1

This beta introduces conservative, fail-safe protocol detection for TSUN Local 1.6.2 and includes the latest read-only protocol coverage work.

This prerelease is intended for real-hardware validation before 1.6.2 stable.

## Automatic protocol detection

- Logger firmware is used only as the first protocol to try.
- All validated runtime families (`1511`, `1097`, `02B0`) can be evaluated when needed.
- A candidate must first pass the existing protocol/transport validation, then reach at least **80/100** confidence.
- If another valid candidate is within **20 points**, detection stops as ambiguous instead of guessing.
- Zero production is neutral, so setup is intended to remain valid at night.
- Once a protocol is selected and stored, normal polling never switches family automatically.

## Manual and Reconfigure

- Manual `1511`, `1097` and `02B0` selections remain strict: the chosen family must validate and there is no silent fallback.
- Reconfigure now allows Auto, Force detection, 1511, 1097 or 02B0.
- Reconfiguration is transactional: the existing entry remains unchanged unless the new connection/protocol validates successfully.

## Protocol coverage

- 02B0 read-only diagnostic/signature coverage now includes `0x2011..0x2013`, `0x202D..0x205F` and `0x302B..0x302F`; the additional values remain raw pending semantic validation.
- 1097 is classified as the validated **GEN4** family, including the Sunology PLAY2 GEN4 path.
- Experimental `3026` remains diagnostic-only and is not part of runtime automatic detection.

## Validation requested

Please test normal setup and Reconfigure on known 1511, 02B0 and 1097 hardware. In particular, report any case where Auto refuses a known device, selects an unexpected family, or a deliberately wrong manual family is accepted.

## Safety

TSUN Local remains local and strictly read-only. This beta adds no inverter configuration or write operation.
