# TSUN Local 1.6.1

TSUN Local 1.6.1 promotes the validated 1.6.1 beta series to stable. The integration remains fully local and read-only, with no inverter configuration or control writes.

## Communication resilience

- Reuse one TCP session across a healthy polling cycle on 1511, 02B0 and 1097.
- Retry one failed protocol block once on a fresh connection instead of immediately invalidating otherwise valid telemetry.
- Keep requests sequential through the existing per-logger FIFO so one slow logger does not block unrelated devices.
- Keep alarm and advanced diagnostic reads best effort.
- Preserve adaptive polling and the existing offline/failure thresholds.

## Energy reliability

- Keep the latest valid AC/PV energy values available across temporary communication loss and Home Assistant restarts.
- Use Home Assistant local midnight as the only displayed daily-energy boundary.
- Advance daily AC/PV energy primarily from monotonic total-energy deltas.
- Ignore hardware daily-counter resets at sunrise or other times, including the PLAY2 / 1097 reset observed around 18:00.
- Recover same-day missed production after a Home Assistant restart when persisted tracking references are available.

## Logger Wi-Fi signal

- Preserve the last valid logger RSSI across one transient five-minute HTTP refresh miss.
- After two consecutive RSSI refresh misses, mark **Logger Wi-Fi signal** unavailable instead of keeping an indefinitely stale value.
- Never synthesize `0%` when an RSSI read fails.
- Restore the real signal immediately on the next successful logger metadata read.
- Apply the same RSSI freshness policy to 1511, 02B0 and 1097.

## Compatibility and regression safety

- Keep the validated protocol register maps and decoders unchanged.
- Keep existing entity keys, protocol framing, PV-input handling, alarms, firmware information and advanced diagnostics unchanged outside the targeted resilience fixes.
- Keep the integration local and strictly read-only.

## Validation

The 1.6.1-beta.6 source passed the complete unit-test suite, HACS validation and Home Assistant Hassfest before promotion. The stable release contains no functional change from beta.6; only stable release metadata and documentation are updated.
