Your model may already be compatible

TSUN Local 1.6.0 detects supported local protocol families, not only a fixed list of commercial model names. The validated families currently include 1511 and 02B0, while 1097 support remains experimental.

✅ An unlisted model does not mean an unsupported model.If your inverter exposes a supported local protocol, automatic discovery may already be enough.

Python / command line — all platforms

Python remains the most direct way to run the diagnostic. The standalone tsun_dump.py uses the same strictly read-only dump engine and works with Python 3.10+ on Windows, macOS and Linux.

Download tsun_dump.py SHA-256 checksum Full Python guide
Recommended full diagnostic
macOS / Linux
python3 tsun_dump.py --full
Windows
py tsun_dump.py --full

Automatic discovery captures all detected TSUN loggers. To target one known logger or a routed subnet, use:

Known logger
python3 tsun_dump.py --host 192.168.1.50 --full
Routed subnet / VLAN
python3 tsun_dump.py --network 192.168.1.0/24 --full

On Windows, replace python3 with py in the commands above.

Desktop diagnostic for Windows, macOS and Linux

Prefer a packaged application? The desktop GUI is 1.5.11 with dump engine 2.7.4. Every package is built from the same shared interface and published through the stable rolling diagnostic-latest release. The historical Windows download URL is unchanged, so older links remain valid.

Which Mac will I need? Mac with an Apple chip M1, M2, M3, M4 or newer → Apple Silicon. If Apple menu → About This Mac says Intel → Mac Intel.
🟠 macOS — read this before the first launch

TSUN Local Diagnostic is not yet notarized by Apple. macOS may block the first launch. You do not need to disable Mac security or Gatekeeper.

  1. Download and unzip the package for your Mac.
  2. Try to open TSUN Local Diagnostic.app once.
  3. If macOS blocks it, click Done.
  4. Open Apple menu → System Settings → Privacy & Security.
  5. In Security, click Open Anyway for TSUN Local Diagnostic.
  6. Authenticate, then confirm Open.

🟢 Once the application opens, you are done. The exception applies only to TSUN Local Diagnostic; normal macOS protections remain enabled.

Four clear steps

1Disable TSUN Local

Temporarily disable the affected config entry in Home Assistant to avoid two simultaneous polling sessions on the logger.

2Run the diagnostic

Use the Python command above or launch the desktop application. Discovery, protocol detection and evidence capture are read-only.

3Direct upload

Recommended in the desktop app. Add an optional tester name and micro-inverter models, review the consent, then upload. You receive a TSL receipt and a link to view exactly what was sent.

4Manual fallback

If direct upload is unavailable, send the generated JSON manually by e-mail. Re-enable TSUN Local when the capture is complete.

What the diagnostic investigates

The read-only engine discovers local TSUN loggers, identifies 1511 / 02B0 / 1097 protocol families, captures known-safe register ranges and gathers bounded passive logger metadata. It can recognize multiple Wi-Fi RSSI layouts in percent or dBm and, in full mode, test whether the logger answers the read-only AT+WSDNS DNS getter without storing the returned DNS address.

✅ It worksReport the exact model and result so the hardware can be added to the validated compatibility list.
❌ It fails or becomes unavailableThe report preserves protocol evidence that can distinguish a register-range issue, logger response marker, firmware variant or communication behaviour.

Safety and privacy

The hardware diagnostic remains strictly read-only. Direct upload is a separate HTTPS action and happens only after explicit consent. The consent state is never remembered.

After upload: the app shows the unique TSL-... receipt and a private-token Worker link that displays exactly the anonymized report submitted by that tester. It does not expose the private reports repository or reports from other users.
